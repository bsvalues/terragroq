XN-02 — live controls on HERMES
Lane: CROSSNODE-SYNC REPAIR (CONT-EXPV2-CROSSNODE-SYNC-STILL-ON-F)

WHY THESE ARE THE TESTS. No .ps1 in this repository runs in CI. `.github/workflows/ci.yml` runs
vitest over `tests/**/*.test.{ts,tsx}` and a Next production build; `work-context.yml` runs the
work-context receipt. Nothing invokes PowerShell, and `vitest.config.ts` include is
`["tests/**/*.test.{ts,tsx}"]`. So these scripts cannot be proven by opening a pull request. They
are proven by running them on the machine they run on, and that is what is recorded here.

Every control is launched through Start-Process with stdout and stderr redirected to files. That
is not decoration -- see XN-03.

--- LC-03  refusal: the archive disk is not there --------------------------------------------
  ... -ResolveOnly -ArchiveVolumeLabel NO_SUCH_LABEL_XYZ
  EXIT=1
  ERR CROSSNODE_SYNC_FAILED code=ARCHIVE_VOLUME_ABSENT stage=PREFLIGHT_RESOLUTION
      ARCHIVE_VOLUME_ABSENT no mounted volume is labelled 'NO_SUCH_LABEL_XYZ'. The archive disk is
      not attached, or its label changed. Nothing was copied in either direction.

--- LC-04  refusal: the registry cannot say where ATLAS is -----------------------------------
  ... -ResolveOnly -FabricRoot <empty directory>
  EXIT=1
  ERR CROSSNODE_SYNC_FAILED code=FABRIC_REGISTRY_UNREADABLE stage=PREFLIGHT_RESOLUTION
      FABRIC_REGISTRY_UNREADABLE ...\fabric-empty\nodes.json does not exist, so atlas's address
      cannot be resolved. Refusing rather than falling back to a written-down address that may now
      name another machine.

--- LC-05  refusal: there is an address but no verified identity to reach it -----------------
  ... -ResolveOnly -FabricRoot <dir holding only a valid nodes.json>
  EXIT=1
  ERR CROSSNODE_SYNC_FAILED code=FABRIC_IDENTITY_UNREADABLE stage=PREFLIGHT_RESOLUTION
      FABRIC_IDENTITY_UNREADABLE ...\fabric-nokey\keys\williamos-fabric does not exist, so no
      authenticated transport to ATLAS can be built. Refusing rather than falling back to whatever
      identity the calling account happens to hold.

  LC-03/04/05 are the point of the repair, not decoration around it. The failure this system keeps
  producing is not a crash; it is a green run that protected nothing. Each of these is the moment
  where the old code would have carried on: New-Item -Force would have built an archive tree on
  whatever F: had become, and a written-down address would have kept naming a machine that is now
  somebody else's.
