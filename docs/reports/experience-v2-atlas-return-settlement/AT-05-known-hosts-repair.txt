The trap this closes: the fabric known_hosts already carried an entry for 192.168.88.8 —
pinned to OMEN's key, left over from when OMEN held that lease (OMEN's own registry note
records the churn: 'the DHCP lease moved .8 -> .7 -> .8 in a day'). ATLAS now holds .8 and
presents its own key, so every StrictHostKeyChecking=yes connection to ATLAS — which is what
sync-models-to-forge.ps1 uses — would have refused on a host key mismatch.

The edit is guarded: it asserts BOTH pins are exactly what it expects before changing
anything, and refuses otherwise. A backup is preserved. OMEN keeps its 'omen'/'omen.local'
pins, which is how OMEN is actually addressed.
